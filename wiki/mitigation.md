# 怎麼減少幻覺

## IBM 列出的方法（偏向企業與開發者）

| 方法 | 說明 |
|---|---|
| 使用高品質的訓練資料 | 「garbage in, garbage out」：用不完整、有偏見或不正確的資料訓練，就會得到同樣的輸出；應使用多元、平衡、結構良好的資料 |
| 慎選與 fine-tune 模型 | 通用模型在訓練資料稀少的專業領域較容易幻覺，針對特定領域的模型較不容易捏造細節。用精選的領域範例 fine-tune，能讓模型學會專業用語、答案格式，以及什麼時候資訊不足、不該臆測。若跳過 fine-tuning 或用品質差的資料，模型較容易幻覺 |
| RAG（Retrieval Augmented Generation） | 把模型接上精選的知識庫，要求它只用知識庫的內容回答，並常附上引用或原文，讓答案來自可信資料，而不是模型自己的聯想 |
| Prompt engineering | 結構不良或模糊的 prompt 可能引發幻覺，讓模型去猜使用者要什麼。結構化的 prompt 會指定任務、輸入格式、輸出格式和規則，例如「若文件沒有明確提到風險，不要自行推論」；也常搭配「不確定就說不知道」這類防護規則。另可使用資料範本（可重複使用、統一使用者與模型溝通方式的預設格式）與 chain-of-thought prompting（要求模型分步驟推理，而不是直接給答案） |
| Human in the loop | 在幻覺可能造成重大傷害的地方（例如法律意見、法規文件）安排人工審核，把生成式 AI 當成起草與研究助手，而不是權威；人工審核也會產生回饋，用來改善 prompt 和系統設定 |
| 監控與評估 | 減少幻覺不是一次就能解決，需要持續監控模型在哪裡、什麼條件下出錯；方法見 [[detection]] |
| AI governance | 預設模型輸出可能出錯來設計管控，例如依風險分級：高風險用途（法規文件、法律文件）要求嚴格查證所有事實，低風險用途（內部腦力激盪、草擬 email）可較寬鬆；也要明定誰負責幻覺風險、在流程中嵌入審核步驟（例如送給客戶前要有「已查證」狀態），並讓員工把 AI 輸出當成必須檢查的草稿 |

## OpenAI 的方法：改變評估的給分方式，並允許放棄不答

| 方法 | 說明 |
|---|---|
| 答錯扣分比不確定更多 | OpenAI 認為有一種簡單的修正：模型自信地答錯時，扣得比表達不確定時更多；模型適當表達不確定時，給予部分分數。OpenAI 也說這個概念並不新，有些標準測試早就用答錯倒扣、留白給部分分數來抑制亂猜 |
| 更新主流評估，而不是只加幾個新測試 | OpenAI 認為，單是添加幾個考慮不確定情況的測試還不夠，需要更新廣泛使用、以準確率為準的評估方法；如果主要成績表繼續獎勵幸運猜中，模型就會繼續學著猜 |
| 允許放棄不答 | （出自原文「為考試而教」一節）OpenAI 的模型規格規定，表達不確定或要求釐清問題，比自信地提供錯誤資訊來得好 |

## 不同來源的說法

- IBM 的方法多從企業與開發者的角度出發（訓練資料、fine-tune、RAG、prompt、人工審核、治理）；OpenAI 則把重點放在模型的訓練與評估方式。
- IBM 認為幻覺只能減少、無法完全消除；OpenAI 認為模型可以在不確定時放棄不答，因此幻覺並非不可避免（見 [[definition]]、[[myths]]）。
