# slides-loop：Loop 版教學簡報規格

這份規格是把階段一（一句話 prompt）之後「人工一直修」的內容寫下來，讓 AI 依規格反覆修正，人只看最後的報告。
階段一的問題紀錄：`slides/v1_prompt/check.md`、`slides/v1_prompt/review.md`，以及使用者的三點意見（不要每張小結、沒有圖、風格太嚴肅）。

## 🎯 目標

只用 `wiki/` 的內容，做一份給「用過 ChatGPT、但不懂技術的大學生」看的教學 HTML 簡報，主題「LLM 幻覺是什麼」。
產出：`slides/v2_loop/index.html`（單一檔案）。

## 🚧 限制

### 內容

1. **只能用 wiki/ 的內容**，不可讀 `raw/`，不可加入自己的知識。
2. **不可自己下結論或給建議**：不寫 Wiki 沒有的評價、歸納、建議（階段一的例子：「錯得有說服力」「最容易落地的做法」「適合入門理解」「各來源共同的建議」）。
3. **保留保留語氣**：Wiki 寫「可能」「通常」「常常」，簡報就照寫。
4. **說清楚是誰說的**：觀點要標明來源（IBM／OpenAI／Anthropic／Ji et al.／Huang et al.）；只有部分來源這樣說時，不可寫成「大家都」「各來源共同」。
5. **不同說法並列**：例如「能不能避免」「分類方式」，並列呈現，不判斷誰對。
6. **例子要標真假**：Wiki 的 examples 頁標為「示範例子」「假設情境」的，不可放在「真實例子」標題下，畫面上要標出。
7. **對讀者友善**：術語第一次出現時用 Wiki 裡的白話說明；太技術的內容（softmax bottleneck、exposure bias、各種方法名稱）不放；一張只講一件事。

### 版面與風格

1. 8–15 張。第 1 張封面（`data-type="title"`），最後一張是整份的總結（`data-type="summary"`）。**其他投影片不放「小結」**。
2. 每張內容投影片開頭是一句核心重點（`class="core"`），接著是細節。
3. **聊天室風格**：幻覺的例子做成 ChatGPT 式的對話框（使用者問、AI 答），AI 答錯的部分用醒目顏色標出；整體明亮配色、圓角色塊、大字。
4. **要有圖**：用 inline SVG 自己畫（流程圖、長條圖、圖示、示意圖），不用外部圖片或網路資源。至少一半的內容投影片有圖。數據（例如 SimpleQA）畫成圖表。
5. 單一 HTML，不依賴外部套件或字型，左右鍵翻頁，1280×720 畫面下不可溢出；字級在投影時後排也看得清楚（內文至少約 22px）。

### 出處標記（程式檢查用）

- 每張投影片是 `<section class="slide">`。
- 每個重點元素（`.core`、`li`、`.point`、`.bubble`）都要加 `data-src="slug1,slug2"`，slug 是 wiki/ 中的頁面（例如 `causes`、`sources/openai`）。
- 畫面上只在每張右下角顯示一行小標籤，例如「出處：Wiki／成因、例子」，由 data-src 自動產生。

## ✅ 完成標準

### 程式檢查（`python3 scripts/check_slides.py slides/v2_loop/index.html`）

S1 張數 8–15；S2 每個重點都有出處；S3 出處頁面存在；S4 數字在引用的頁面找得到；S5 每張有核心重點、最後一張是總結；S6 1280×720 不溢出。**全部 0 錯誤。**

### AI 審查（新對話，只給簡報與它引用的 wiki 頁面）

- F1 無依據、F2 不忠實：**0 項**。
- F4 教學性（太難、太擠）：只提醒，但每輪要處理。

審查者不可以是寫簡報的同一個對話。

## 🔁 每一輪做什麼

1. 第 1 輪：依本規格產生完整簡報。
2. 跑程式檢查 → 另開新對話做 AI 審查 → 報告存成 `slides/v2_loop/round<N>_check.md`、`round<N>_review.md`。
3. 下一輪：**只修報告列出的問題**，其他地方不動；改完再檢查、再審查。

## 🛑 停止條件

- 程式檢查 0 錯誤且審查 F1、F2 為 0 → 交件。
- 改滿 3 輪仍未全過 → 停下，交出目前版本與最後一輪報告，由人決定。
- 開始前，Wiki 中相關頁面少於 3 頁 → 不開始。
